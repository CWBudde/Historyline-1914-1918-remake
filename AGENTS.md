# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, …) working in this repository.
`CLAUDE.md` just imports it.

## What this is

A Go/Ebitengine port of a Python/pygame remake of the Amiga game Historyline 1914-1918. `PLAN.md` is the
roadmap and the source of truth for what is done (tick boxes only with evidence you ran). Everything
inherited from upstream lives in `legacy/` (see `legacy/README.md`): the Python code in `legacy/python/`
(`main.py`, `gui.py`, `hlrData.py`, `mapEditor.py`, `ArtificialIntelligence*.py`) is the **reference
implementation**, kept until Go reaches parity, and the upstream art is `legacy/python/gfx/` (reference only,
never shipped). Python reads `gfx/` by cwd-relative path, so run it from `legacy/python/`; it reads the shared
`levels/` at the repo root. `internal/tpwm/testdata/00.FIN` is a sample DOS level for `internal/tpwm`.

## Language policy

Write new code and tooling in **Go**. Python is acceptable only for the existing reference code and the
remaining tool `tools/art-inventory/` and the research test `tools/original-rules/test_fixture_schema.py`;
do not add new Python tools. Ports of those to Go are welcome.

## Commands

```sh
just ci          # everything CI runs: lint, test, build, wasm, gfx-check
just test        # go test ./...
go test ./internal/game -run TestName   # single test
just lint        # go vet + golangci-lint v2 (.golangci.yml)
just run         # play; just build -> bin/historyline; just wasm -> bin/; just web 8080 -> build/web (served by cmd/serve)
just py level1_cp                      # run the Python reference (cwd legacy/python)
python3 -I -m unittest discover -s tools/original-rules   # fixture-schema test (not in just ci)
```

Run Python tests with `-I` and from the repo root. After a same-size `sed` edit of a `.py` file, delete
`__pycache__` or Python uses the stale `.pyc`.

## Architecture

- `cmd/historyline`: the Ebitengine front end.
- `internal/game`: rules engine with **no rendering**; UI and AI drive it through commands
  (`commands.go`). Movement, vision, combat live beside it. Rule behaviour is pinned to the Python
  reference by `testdata/python.json`, generated by `testdata/gen_python.py` from `gui.py` rule functions
  run on the game's own tables.
- `internal/data`: embedded JSON tables. Terrain and the weapon catalogue are ported from `hlrData.py`;
  unit stats and per-slot attacks come from the original `UNIT.DAT` of the free DOS demo
  (`testdata/unitdat.json`, numbers only). The catalogue is bound to the weapon art, so change attack
  values in a unit's slot, never in `weapons.json`.
- `internal/hexgrid`: Python's hex layout (even lines `Width` hexes, odd lines `Width-1`, half-shifted).
- `internal/tpwm`: Turbo Packer unpacker; the size byte order (DOS little, Amiga big) is a parameter.
- `internal/level`: `levels/*.json` read/write; `Marshal` reproduces `mapEditor.py` byte for byte.
- Rule sets: `Classic` (Python's rules) and `Standard` (improved). Neither is original-game fidelity.
- `tools/original-rules` (R0–R5 in PLAN.md): static disassembly of the DOS `HL.EXE` is `cmd/dosexport`
  (`internal/dosexe` parses the MZ image and records); the 8086 interpreter is `internal/dos8086`, and `internal/dosoracle` holds the runners and the
  independent transcriptions that are compared against executed code. Findings live in
  `docs/research/original-dos-rule-spec.md` (profile `dos-0.1`) with an evidence status per rule.
- `tools/art-inventory`, `tools/art-review`, `tools/native-reference`: graphics tooling (`just gfx-check`).

## Repo rules

- **Commit straight to `main` and `git push origin main`**; no branches or PRs, never force-push. Commits
  end with the `Co-Authored-By:` trailer given by the harness.
- `origin` is the fork CWBudde/Historyline-1914-1918-remake, `upstream` is PoulKalff; pass
  `-R CWBudde/Historyline-1914-1918-remake` to `gh`.
- `original/` (supplied DOS/Amiga installations) and `build/` are git-ignored. Never commit original
  bytes, listings or strings; fixtures hold numbers only. Generated binaries go to ignored `bin/`/`build/`.
- `docs/manual/` is the user's reconstruction of the original manual: leave it alone.
- The graphics track (G0) runs in parallel by the user: do not edit `art/`, `docs/art/`, `tools/art-review/`.
  `.worktrees/` holds isolated checkouts for it.
- `PLAN.md` often has uncommitted user edits: stage only your own hunks.
- Never touch the `Large` drive (`/run/media/christian/Large`).
