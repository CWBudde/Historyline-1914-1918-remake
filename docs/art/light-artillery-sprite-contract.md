# Light-artillery sprite contract

2026-10-15. [Gallery](light-artillery-review.html) ·
[Batch evidence](distinct-units-batch-20.md) ·
[Manifest](../../art/unit-light-artillery-v1.json) ·
[Recipe](../../art/recipes/unit-light-artillery-v1.json).

The bounded `-unit` exporter now supports two explicit families: `infantry` and
`lightArtillery`. The latter binds only `CP_lArtillery` and `EC_lArtillery`.
Medium/heavy artillery remain separate families without replacements. Current
owner independently selects `cp`, `ec` or `neutral`; class/country and owner
colour must stay distinct when a gun is captured.

The new atlas depicts one generic WWI light field gun with two crew in each of
six separately authored views. It uses two spoked wheels on one axle, a shield,
long barrel and single box trail. It is an illustrated family candidate, not a
claim to model the specific German/French weapons in the rules tables. The exact
initial generation and edit chain and unchanged generated bytes are retained.
The first study was too large beside infantry. The edit requested 72% whole-group
framing, but the generated change is approximate: the reviewed N gun length is
about 364 source pixels versus 453 initially. Do not treat the edit as a measured
exact affine or independently rescale its parts to force that claim.

The row-major 512×512 panels are `N, NW, SW, S, SE, NE`. Muzzle direction defines
heading, with the trail behind the breech and the crew at its rear quarters.
The elevated camera and upper-left lighting stay fixed across all views. The
source is not produced by rotating or mirroring a finished shaded sprite.

All geometry, filtering, recolouring and state rules use the existing
[infantry pipeline](infantry-sprite-contract.md):

- Keep every whole panel with one shared 0.8 export framing factor.
- Use a 96×96 logical unit canvas, top-left at terrain origin `(0,-9)` and
  registration anchor `(48,49)` mapping to terrain `(48,40)`.
- Export neutral base and tint-energy mask at 384×384, then independently
  reduce each whole plane with premultiplied alpha-aware Lanczos3 to 192×192.
- At each final density, compose the same CP/EC/neutral palette from saved planes.
  Mask alpha equals base alpha; mask RGB is tint energy rather than coverage.
- Spent state takes the tinted red channel for all three RGB channels, preserving
  alpha. Neutral normal retains coloured wood/skin/leather and differs from spent.
- Keep the six-world-pixel zero-RGBA outer guard. Do not clip units to terrain
  ownership polygons, remove low-alpha pixels, or independently crop/scale views.

Magenta painted gun surfaces and crew clothing are temporary technical control
colours. Metal, skin, wooden spokes and leather retain their own material colours
where the extracted tint energy is zero. The same exact smooth key/neutralization
formula and signed-lobe Lanczos handling apply. Final RGB clamps are required;
filtered tint energy can exceed a neutral channel. Coloured 2× sprites are composed
after plane reduction, so they are not claimed to equal reductions of coloured 4×.

The 24 saved scenes use grass, snow and canonical mud-with-six-grass-neighbors,
both line parities, normal/spent and both densities. Each has seven real pinned
ground PNGs followed by seven decoded exported unit PNGs with ordinary Over.
Canvas size, world origins, stable y/x draw order, registration and outward ring
facings match the infantry fixtures. The centre is neutral north-facing
`CP_lArtillery`; NE deliberately uses `CP_lArtillery` with EC ownership, and NW
uses `EC_lArtillery` with CP ownership. Default class assignments alternate before
those explicit overrides. These are visual cases, not legal capture-command tests.

The report records class/family, palette, state, facing, source rectangles, full
placement and every source/output pin. Tests independently select the expected
sprite filename and verify nested sprite/ground provenance before scene assembly
for both families. The previous infantry bundle must remain byte-identical.

This delivery does not install a runtime replacement. The fixed anchor derives
from the reference blit, not recovered wheel/boot contact. Native Amiga A–F mapping,
motion/turn stability, full-map readability, fog/selection, fractional zoom,
Blender comparison and release acceptance remain open. Portraits, panel graphics
and other unit families remain separate work before Phase 2.
